Under the Hood

Audio Architecture

TARGET ENGINE RUNTIME: CHROMIUM / WEBKIT / GECKO (WASM SIMD ENABLED)
01 / CONCURRENCY

AudioWorklet Thread Isolation

The real-time audio thread never touches the DOM or the page's garbage-collected heap. Lock-free ring buffers carry every change across, so a busy page doesn't stop the sound.

02 / DSP PERFORMANCE

WebAssembly 128-bit SIMD

The engine is written in Rust and compiled to WebAssembly with SIMD: mixing, synthesis and filters work on four samples per instruction.

03 / DISK I/O

Origin Private File System (OPFS)

Samples are cached on your disk by their content hash, and long recordings stream straight from it instead of filling memory.

04 / COLLABORATION

Up to Five in One Project

Edits merge as they happen, without locks: nothing is overwritten and nobody waits. Solo and the view stay your own.

05 / OFFLINE

Offline-First Projects

Projects live in your browser. Keep working without a connection; your changes merge back once you are online.

06 / OPEN SOURCE

AGPL-3.0, on GitHub

The engine and the app are open source. Read the code, follow along, or open an issue.

07 / HARDWARE PROTOCOL

WebMIDI Controllers

Play the piano roll from a MIDI keyboard and turn knobs from a controller. No drivers to install, and the setup stays on your device, not in the project.

08 / MODULAR EXTENSIONS

Sandboxed Plugins

Instruments and effects by others, as WebAssembly modules in a sandbox: no network, no page, no reach into the engine, only what it hands them.

09 / EXPORT INTEGRITY

Offline Render (Bouncing)

Export runs the same engine in a worker, faster than real time, so the file sounds exactly like playback.
